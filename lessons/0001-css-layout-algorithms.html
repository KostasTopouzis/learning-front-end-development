CSS Is a Set of Layout Algorithms

The missing piece behind “I know Flexbox and Grid, but CSS still surprises me.”

Why this, why now

Your first portfolio piece (P1) is a responsive, image-rich site. Most “my layout broke” and “my image has a weird gap” bugs come from the same blind spot. Learning one CSS property at a time hides the system that decides what each property means. This lesson gives you that system. It takes about 25 minutes.

A CSS property has no single meaning. It is an input, and the layout algorithm the element is in decides what to do with it.

You probably learned CSS as a dictionary: width sets the width, margin adds space, z-index controls stacking. That model works until it doesn't, and then CSS feels random. Josh Comeau calls this the moment to switch to a different question: not “what does this property do?” but “how does this layout algorithm use this property?”Comeau, “Understanding Layout Algorithms”. The spec calls these layout modes or formatting contexts (MDN). Different names, same idea.

Who chooses the algorithm?

Mostly the parent. A parent's display value picks the algorithm its children are laid out with. The element's own position can pull it out into a different one.display has two parts: how the box behaves outside (block or inline) and how it lays out its children (flow, flex, grid). display: flex means “block on the outside, Flexbox for my children.” See MDN: display.

There are others (table, multi-column, float), but these four cover nearly everything you'll build in P1.

One extra rule for Flow. Flow treats children differently based on the child's own outer display. Block children (div, p) stack and respect width. Inline children (span, a, strong) flow along the line like words, sized by their content. Flexbox and Grid ignore this distinction: every child becomes a flex or grid item.MDN: inline-level content. The spec calls the Flexbox/Grid conversion blockification.

1 · width is a rule in Flow and a suggestion in Flexbox

The child asks for width: 2000px inside a 300px parent. Predict what each preset does, then click it. The readout under the playground measures the real rendered size.

In Flexbox, width feeds the item's flex-basis, a hypothetical size. flex-shrink defaults to 1, so the item is allowed to shrink to fit.Try adding flex-shrink: 0; to .child in the Flexbox preset. Background: Comeau, “An Interactive Guide to Flexbox.” Flow has no concept of shrinking, so the child overflows.

2 · Margins collapse in Flow and nowhere else

In Flow, adjacent vertical margins merge and the larger one wins: 24px, not 40px.MDN: Mastering margin collapsing. Flexbox and Grid don't do this. This is one reason many developers reach for gap instead of margins in flex and grid layouts.

3 · The mystery gap under images (your P1 bug, pre-solved)

The frame below should hug its 90px-tall image. Compare the two heights in the readout.

In Flow, an <img> is an inline element. It's laid out like a word of text, sitting on the text baseline, with room left underneath for letters like “g” and “y.” That room is the gap. Fix A changes the image's own display. Fix B moves the image into a different algorithm (Flexbox) where inline text rules don't apply.This exact case is the worked example in Comeau's article. It also explains why many CSS resets include img { display: block; }.

In Tailwind

You may never have seen this bug, because Tailwind's base reset, Preflight, makes images and other replaced elements block-level for you. That's Fix A, applied globally. It's a good illustration of a general point: Tailwind doesn't change the algorithms, it just picks some defaults for you. When you add inline or inline-block to an <img>, or work in a codebase without Preflight, the gap comes back. Now you know why.

The other demos in Tailwind terms: Fix B is flex on the parent; opting out of shrinking is shrink-0; and flex flex-col gap-4 replaces margin-based spacing.

The habit to build

When a property “does nothing” or does something strange, and DevTools shows the declaration is applied (not crossed out), ask these questions in order:

  1. Which algorithm is this element in? Inspect the parent's computed display. Chrome shows flex/grid badges next to the parent in the Elements panel.DevTools: flexbox · DevTools: grid
  2. Did the element leave it? Check its own position.
  3. How does that algorithm use this property? This is where you look things up.

Check yourself

Answer from memory, without scrolling up. Only your first click counts toward the score.

A parent has display: flex; width: 300px. Its empty child has width: 2000px. What width does the child render at?

In Flexbox, width is a hypothetical size (the flex-basis), and flex-shrink: 1 is the default, so the item shrinks to fit. The same CSS in Flow overflows.

Normal Flow layout: .a { margin-bottom: 24px } is directly followed by .b { margin-top: 16px }. How much space is between them?

Margin collapse: in Flow, adjacent vertical margins merge and the larger one wins.

Same two elements, but now the parent is display: flex; flex-direction: column. How much space now?

Margin collapse is a Flow rule. Flexbox doesn't implement it, so both margins apply: 24 + 16.

An <img> inside a bordered <div> has a few pixels of empty space below it. What causes it?

In Flow, images are inline. They sit on the text baseline, and space is reserved below for descenders. Fix it with img { display: block } or by making the parent a flex container.

Inside a paragraph you write <span style="width: 200px">hi</span>. What happens?

The <p> is block, so its children are laid out with Flow. But the width is on the span, which is inline. Flow lays out inline elements like text, and width doesn't apply to them. Use display: inline-block, or make the paragraph flex so the span becomes a flex item.

A child of a display: grid container has z-index: 2 and no position set. Does the z-index take effect?

The Flexbox and Grid algorithms both honour z-index on their items without position. Flow is the algorithm that requires it, which is where the “z-index needs position” rule of thumb comes from. See CSS Grid spec: z-axis ordering.

DevTools shows your declaration is applied (not crossed out), but the property still seems to do nothing. What's the most useful next question?

The declaration is winning, so specificity isn't the problem. The algorithm is choosing to interpret the property differently, so find out which algorithm it is.

Retrieval prompt: say it out loud before opening

Name the four layout algorithms from this lesson. For each, give one property it treats differently, and say what decides which algorithm an element is in.

Answer: Flow (margins collapse, width ignored on inline), Flexbox (width is a shrinkable suggestion), Grid (z-index without position), Positioned (leaves its parent's algorithm; offsets from the containing block). Mostly the parent's display, plus the element's own position.
